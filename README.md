# 流域洪水预报与水库群联合调度系统

基于水文模拟引擎的流域级洪水预报与水库群削峰错峰调度演示系统：覆盖 **降雨—产流—汇流—河道演算—水库调洪—联合调度—预警与转移** 全链条。

![Tech](https://img.shields.io/badge/Backend-FastAPI%20%2B%20SQLite-009688) ![Tech](https://img.shields.io/badge/Frontend-Vue3%20%2B%20SVG-42b883) ![Tech](https://img.shields.io/badge/Python-3.10%2B-3776AB)

---

## 功能特性

- **水文模拟引擎**
  - SCS-CN 曲线数法产流（含初损扣损）
  - 三角单位线汇流（面积—时段守恒折算）
  - 马斯京根法河道演进（C0+C1+C2=1 保证稳定）
- **水库调洪演算**：库容—水位—泄流三曲线耦合的固定点迭代，支持闸门开度过程线；出流受「库容+时段入流」可用水量约束，杜绝空库凭空泄流
- **三工况对比**（削峰率以天然过流为基准）
  - `natural` 天然河道过流（无水库调蓄，最坏基线）
  - `rule` 常规调度规则（非汛情期顺水控泄，强降雨峰前预泄腾库）
  - `optimized` 联合优化调度（倍率扫描 + 错峰错时微调，保证不劣于前两者）
- **预警与转移**：站点水位分级预警（蓝/黄/橙/红）、淹没风险区评估、强制转移记录与转移路线可视化
- **联合防汛处置协同**：围绕预报运行的「调度员发起 → 预警值守审核 → 转移负责人执行 → 完成」四态闭环；审核通过自动把调度方案回写水库工况、预警与转移台账，完成闭环统一销警与转移到位，历史运行记录自动兼容
- **处置单滚动接收新一轮预报**：已审核处置单（待执行/资源已调度/执行中）可滚动绑定新一轮预报运行，方案快照按轮次演进；预警按站点、转移按风险区做**身份迁移式增量调整**（等级/峰值/受威胁人数刷新，处置中/已销警/转移中/已到位等人工状态与避难点挂接保留）；新风险区增量挂接形成资源缺口、旧风险区解除台账保留不抹除；`approved/resourced` 按新方案末态回写水库工况，`executed` 维持实际运用工况只更新方案目标；已出库物资不回滚、执行中车辆不动，追加车辆即派即发，指挥员再确认调度令仅出增量
- **应急资源与避难点协同调度**：审核通过后，转移负责人分配避难点容量、物资管理员分配车辆与物资、指挥员确认资源调度令（可选环节）；容量/运力/库存跨处置单统一占用校验，确认调度令时物资出库、避难点回写转移进度、风险预警进入处置中；执行发车、闭环归队并释放资源份额
- **枯水期供水保障**：水库管理员申报分乡镇配水计划 → 调度员审核（登记枯水/供水预警）→ 乡镇逐户确认供水优先级并启动执行配水 → 完成时按实际供水量**扣减库容（死水位为不可突破底线）**，回写**水库调度记录**与供水预警（水位仍低则升级、恢复则销警）；异常欠供时物资管理员**追加应急物资直接出库**（复用应急物资库存池，可挂接既有防汛处置单，仅追加处置记录、不改其状态机）
- **预报幂等**：同一降雨情景×调度工况归并为同一次预报运行，重复执行/并发触发/异常重试不会重复新增预警与转移台账
- **可视化前端**：SVG 流域河网拓扑图、实时监测、情景预报对比、闸门运行过程、削峰效果评估

## 使用说明

1. **流域总览** — 青岚江流域河网拓扑、子流域、雨量站、水库与风险区分布
2. **实时监测** — 雨量/水位/水库蓄水状态一览与运行状态着色
3. **洪水预报** — 选择降雨情景（5 年/100 年/10 年一遇），推演 36 小时洪水过程；默认以天然工况展示最不利情形，可切换规则调度与联合优化对比
4. **联合调度方案** — 三工况下游峰值对比、削峰率、闸门开度与库水位过程线
5. **处置协同** — 在「调度员 / 预警值守 / 转移负责人 / 物资管理员 / 指挥员」角色间切换：围绕预报运行发起处置单；预警值守审核后方案回写水库工况与预警、转移台账；审核通过后转移负责人分避难点容量、物资管理员配车辆与物资，指挥员确认资源调度令（容量/运力全覆盖校验、物资出库、回写转移进度与风险预警）；转移负责人启动执行（车辆发车）并确认完成（转移到位、统一销警、车辆归队）。降雨修正后调度员可对已审核处置单「接收新一轮预报」：方案按轮次滚动，预警/转移增量迁移并保留人工状态，新风险区追加资源、再确认调度令只出增量
6. **枯水期供水保障** — 在「水库管理员 / 调度员 / 乡镇 / 物资管理员」角色间切换：水库管理员选择水库与受水乡镇、填报分乡镇配水计划（死水位以上可供水实时校验）；调度员审核并登记枯水/供水预警；乡镇逐户确认供水优先级（1 最高）后启动执行配水，执行期上报各乡实际供水量；乡镇确认完成时按实供水量扣减水库库容/水位、追加水库调度记录，水位仍低于枯水预警线则升级预警、恢复则销警；出现欠供时物资管理员追加应急物资（直接出库，可挂接既有防汛处置单，处置记录追加留痕、状态机不变）
7. **预警与转移** — 分级预警台账、风险区受威胁评估、强制转移路线、指定避难点与人口转移进度

## 预报运行与处置记录的幂等设计

重复执行同一预报（同一 `event_id` + 同一 `mode`）不会产生重复的预警与转移台账：

- **幂等键**：`forecast_runs(event_id, mode)` 唯一约束。触发时先 get-or-create（并发冲突由唯一约束兜底，冲突方改读已存在的运行），进程内按幂等键加锁串行执行。
- **关联**：`warning_records` / `evacuation_records` 通过 `run_id` 挂到预报运行，分别以 `(run_id, target_type, target_id, kind)`、`(run_id, zone_id)` 唯一约束防重。
- **重跑语义**：过程线等纯派生数据同事务先删后插；预警/转移按幂等键 upsert，**保留人工处置状态**（已销警 `cleared`、转移中/完成 `moving/safe` 不被重跑覆盖）。
- **异常重试**：运行先以 `running` 落库作为幂等锚点，派生数据与处置记录单事务提交；失败标记 `failed`，重试自动归并到同一运行补齐缺口。
- **历史记录**：老库执行 `python scripts/migrate_idempotent.py`（幂等，可重复跑）：补充 `run_id` 列（历史记录保持 NULL、原样展示）、清理历史重复、建立唯一索引。

## 联合防汛处置协同

围绕一次预报运行形成跨岗位闭环，`disposal_orders.run_id` 唯一约束保证一次运行至多一单：

| 状态 | 操作角色 | 动作 | 联动 |
| --- | --- | --- | --- |
| `initiated` 待审核 | 调度员 | 发起处置单（重复发起幂等归并） | 归档调度方案快照（峰值/削峰率/各库末水位末库容/闸门过程） |
| `approved` 待执行 | 预警值守 | 审核通过 | **回写**：① 各水库工况更新为方案末水位/末库容；② 本次运行预警、转移台账挂接处置单 |
| `resourced` 资源已调度 | 指挥员 | 确认资源调度令（可选环节） | 容量/运力覆盖校验 → 物资出库、避难点回写转移进度、关联预警进入 `handling` 处置中 |
| `executed` 执行中 | 转移负责人 | 启动执行 | 关联转移记录由「待转移」联动为「转移中」，已调度车辆发车 |
| `completed` 已闭环 | 转移负责人 | 确认完成 | 转移全部置为 `safe`、关联预警统一 `cleared` 销警、车辆归队并释放容量/运力占用 |

### 应急资源与避难点协同调度

审核通过后（`approved`）三类岗位围绕处置单并行分配资源，指挥员确认后形成调度令：

- **转移负责人 → 避难点容量**：按转移行动（风险区）指定避难点与安置人数；跨处置单统一容量校验，其它进行中处置单的占用计入，超分返回 409；同区同点重复分配幂等归并为调整人数。
- **物资管理员 → 车辆**：指定车辆、服务风险区（空为机动运力）与往返趟次（运力 = 核载 × 趟次）；车辆跨处置单互斥，已派出/执行中车辆不可再派，同单重复派车幂等更新。
- **物资管理员 → 物资**：按风险区或处置单公用分配；`approved` 单的分配为库存**预占**（`supplies.stock - 预占 = 可用`），低于安全库存给出预警标识。
- **指挥员 → 确认资源调度令**：逐区校验避难容量与车辆运力（含机动运力池）全覆盖，不足 409 并给出缺口明细；通过后物资按「分配数量 − 已出库数量」**增量出库**（重复确认只出增量，可在调度令后追加分配），主避难点回写 `evacuation_records.shelter_id/shelter_name`，关联预警 `active → handling`。
- **执行 / 闭环联动**：启动执行时车辆 `dispatched → departed`（发车），转移进入转移中；闭环时车辆归队、预警销警、转移到位，处置单容量/运力份额释放，可供后续处置单复用。
- **可选不阻断**：未做资源协同也可直接从 `approved` 启动执行（兼容既有四态流转）；无转移台账的处置单无需资源调度。

- **角色校验 / 状态机**：越权操作返回 403，跳态/重复操作返回 409；每步记录操作人电子签名与时间戳，审核意见/调度令/执行说明/完成小结追加到处置记录。
- **重跑不回滚**：闭环后重跑预报只刷新派生过程线，预警 `handling/cleared`、转移 `moving/safe`、避难点挂接等人工/联动处置状态保持不变（沿用幂等 upsert 语义）。
- **历史运行兼容**：历史预报运行缺少调度方案或水库过程线时，发起环节以 `write_ledgers=False` 自动补算（只写过程线与方案，不回造台账）；`run_id`/`disposal_id` 为 NULL 的历史遗留台账原样保留。老库依次执行 `python scripts/migrate_disposal.py`、`python scripts/migrate_resources.py`（均幂等，可重复跑）补建处置单与资源表、`resourced_*`/`shelter_*`/`issued_quantity` 列及唯一索引；迁移不改变历史处置单状态；执行 `python scripts/migrate_water_supply.py` 补建供水保障 5 张表、水库枯水水位列与乡镇台账。

### 处置单接收新一轮预报（滚动修订）

降雨修正/台风路径调整时，**调度员**可把已审核处置单滚动绑定到新的预报运行（另一个情景/工况），无需重新走发起—审核，全过程单事务：

| 维度 | 增量调整规则 |
| --- | --- |
| 适用状态 | `approved / resourced / executed`（`initiated` 直接重新发起；`completed` 闭环后不再滚动） |
| 调度方案 | 快照滚动为新一轮方案并记录轮次历史（`round/rounds/last_refresh`）；`approved/resourced` 按新方案末水位/末库容回写水库工况，`executed` 不反演正在运用的实际工况 |
| 预警 | 按「目标类型+目标+预警种类」身份迁移到新运行：等级/峰值/阈值/文案刷新，`active/handling/cleared` 人工状态、处置单挂接、首次触发时间保留；新增站点预警增量挂接；新一轮不再预警的站点台账保留不删（继续闭环销警） |
| 转移 | 按「风险区」身份迁移：`pending` 刷新触发方式与受威胁人数，`moving/safe` 保持；新增风险区增量挂接（执行中单自动联动为转移中）；解除风险区台账保留 |
| 避难点/车辆/物资 | 分配记录以转移记录 id 为键，迁移后天然沿用；新风险区形成容量/运力缺口由各岗位追加；执行中只可追加不可撤回，追加车辆即派即发；指挥员再确认调度令时物资**只出增量**（`数量 − 已出库`），已出库份额与执行中车辆状态不动 |
| 并发与冲突 | 处置单与新旧两运行双维度加锁（按 id 定序防死锁）；同一新运行已挂接其它处置单返回 409；未推演完成的运行 409；同一轮次滚动 409 |
| 历史遗留 | 只迁移 `disposal_id` 挂接本单的台账；`run_id/disposal_id` 为 NULL 的历史记录原样保留 |


## 枯水期供水保障

围绕水库抗旱供水形成跨岗位闭环，与防汛处置并存、共用应急物资库存池：

| 状态 | 操作角色 | 动作 | 联动 |
| --- | --- | --- | --- |
| `submitted` 待审核 | 水库管理员 | 提交分乡镇配水计划（周期/水量） | 死水位以上可放水量校验（含跨进行中单据预留）；同库进行中单互斥 |
| `reviewed` 已审核 | 调度员 | 审核通过 | 登记枯水/供水预警（`warning_records.kind=water_supply`，按保障单幂等） |
| `executing` 执行配水中 | 乡镇 | 逐户确认优先级（1 最高）→ 全部确认后启动 | 供水预警 `active → handling` |
| 执行中 | 乡镇 | 上报各乡实际供水量 | 实供 < 计划计为欠供；超计划上报 422 |
| 执行中/已完成 | 物资管理员 | 异常欠供追加应急物资 | 直接扣减 `supplies.stock` 出库；可挂接防汛处置单仅追加处置记录；无欠供 409、超库存 409 |
| `completed` 已完成 | 乡镇 | 确认完成 | 未上报按足额结算；按实供水量扣减库容/水位（**低于死水位 409 拦截**）；追加 `reservoir_dispatch_logs` 调度记录；水位仍低升级枯水预警、恢复销警 |

- **死水位底线**：`reservoirs.dead_level` 为死水位、`drought_warn_level` 为枯水预警线（缺省 0 时按死水位～正常蓄水位 0.4 分位推算）；申报与完成两处做可用水量校验，枯水等级按水位在预警线与死水位间的位置分蓝/黄/橙/红。
- **调度回写**：完成放水追加 `reservoir_dispatch_logs`（`kind=water_supply`），记录放水量、放水前后水位/库容与分乡镇结算，与防洪调度方案台账并存；`GET /api/reservoir-dispatch-logs` 统一查询。
- **历史兼容**：`warning_records.water_supply_plan_id` 关联供水保障单（历史预警 NULL 原样保留）；应急追加不写 `supply_allocations`、不改处置单状态。老库执行 `python scripts/migrate_water_supply.py`（幂等，可重复跑）补建 5 张表与枯水水位列、乡镇台账。
